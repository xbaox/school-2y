## СВОДКА — первой строкой

**Бага фильтра по сроку в колоде НЕТ. Гипотеза A2 опровергнута: `deck()` корректно
исключает выученные слова с ненаступившим сроком.** Улика владельца объясняется
тем, что `cards.seen` за 01.09 сравнивается с состоянием SRS **после** сессии:
55 слов пришли на повтор именно 01.09 (их предыдущий срок был ровно `2026-09-01`),
получили четвёртую оценку и только тогда уехали на 11.09. Точечная разморозка
ради этого не нужна.

**Но фильтр по сроку действительно проломлен — в другом месте: в промпте
минималки.** `PROMPTS.minimal()` строит список слов через `State.oldestWords(15)`
(`state.js:848`), который **не смотрит на SRS вообще**. Сегодня все 15 слов в
промпте разминки — `known` со сроком 11.09. Список одинаков каждый день и будет
одинаковым всегда: `wordBank()` отсортирован по дате урока и не сокращается.
Вот это — настоящий кандидат на точечную разморозку (см. D2).

Три остальные крупные находки:

1. **Колода на 75 % состоит из долгов** (сегодня 13 слов + 40 долгов = 53 карточки),
   и лид-текст «колода со временем становится короче» этому противоречит.
2. **11.09 колода скачком станет 128 карточек** — 55 слов синхронно вышли на
   один и тот же срок (когортная лавина).
3. **ИИ сам выдумывает `[D-N]` для новых долгов.** В B1.3 строка
   `Погашено: [D-11] …` погасила долг, которого в промпте не было, а восемь
   долгов (D-34…D-41) записаны в банк с чужим id внутри текста. Правило 14
   контракта («копируй формулировку ДОСЛОВНО») делает будущую перекрёстную
   ошибку почти неизбежной. Подробно — в «Находках вне списка».

# A. Колода карточек — механика

## A1. Один билдер или два

**Один.** «Листать» в Журнале и «Карточки» в минималке зовут одну и ту же
функцию `Cards.open()`, которая внутри зовёт единственный билдер `deck()`.

| точка входа | файл:строка | что делает |
|---|---|---|
| Журнал → «Листать» | `journal.js:170` | `U.on(host,'click','[data-open-cards]', … Cards.open())` |
| Сегодня → «Открыть карточки» (уровень `min`) | `app.js:480` | кнопка `data-cards` |
| Сегодня → шаг минималки на норме/полной | `app.js:515` | кнопка `data-cards` |
| Экран урока | `lesson.js:306` | `U.on(host,'click','[data-cards]', … Cards.open())` |

Билдер целиком — `journal.js:195`:

```js
  function deck() {
    // выученные слова, у которых срок повтора не подошёл, в колоду не берём
    var words = State.activeWords().map(function (w) {
      return {
        type: 'word', en: w.en, key: 'w:' + String(w.en).toLowerCase().trim(),
        front: w.en, back: w.ru,
        meta: U.fmtShort(w.date) + ' · ' + w.lessonId + ' · ' + statusName(State.wordStatus(w.en))
      };
    });
    var debts = State.openDebts().map(function (d) {
      return {
        type: 'debt', key: 'd:' + (d.did || d.id),
        front: (d.did ? d.did + ' · ' : '') + d.text,
        back: 'долг из ' + d.createdIn + ' · погашено ' + State.debtProgress(d) + '/2' +
          ' · отработан в ' + ((d.clearedIn || []).join(', ') || '—'),
        meta: State.trackName(d.track || 'eng')
      };
    });
    return words.concat(debts);
  }
```

**Состав и порядок:**

1. **Слова** — `State.activeWords()` → `wordBank()` минус «отдыхающие».
   `wordBank()` (`state.js:833`) собирает слова из всех итогов, сортируя итоги
   по дате по возрастанию; дубликаты по `en` (lowercase+trim) отбрасываются.
   То есть порядок — «старые вперёд», ровно как обещает лид.
2. **Долги** — `State.openDebts()` **без аргумента**, то есть **все дорожки**,
   в порядке массива `s.debts` = порядок создания. Долги идут **строго после
   всех слов**, конкатенацией.

Единственный фильтр — по сроку (см. A2). Фильтра по дорожке, по блоку или по
фазе нет.

## A2. КЛЮЧЕВОЙ ВОПРОС — фильтр по сроку. **Опровергнуто**

Фильтр есть и работает. Цепочка `deck() → State.activeWords() → wordResting()`.

`state.js:748`:

`state.js:793`:

  function activeWords(todayIso) {

Есть и регрессионный тест, который это стережёт — `tests/cases.srs.js:116`
(«SRS: колода не берёт отдыхающие слова»); он зелёный.

### Доказательство на живом состоянии

Прогон `Cards.deck()` на экспорте владельца **прямо сейчас** (01.09, после сессии):

```

wordCounts {"active":13,"known":75,"total":88}
```

75 выученных слов **в колоде отсутствуют**. Если бы фильтр не работал, колода
была бы 88 + 40 = 128.

### Почему улика выглядела иначе

Разбор `cards.seen` за 01.09 (61 ключ = 60 слов + 1 долг) против SRS:

| группа | в `seen` 01.09 | итоговая запись SRS |
|---|---|---|
| 55 слов | **да** | `known · streak=4 · step=1 · due=2026-09-11` |
| 19 слов | **нет** | `known · streak=3 · step=0 · due=02–04.09` |
| 1 слово (`to isolate`) | да | `known · streak=3 · step=0 · due=2026-09-05` |
| 1 слово (`all over`) | да | `learning · streak=2` |
| 3 слова (`markup`, `profit margin`, `to collect like terms`) | да | `learning · streak=0` |

**Именно 19 «отдыхающих» слов в `seen` не попали.** Если бы фильтр был проломлен,
они были бы в колоде вместе с остальными и тоже получили бы четвёртую оценку.
Их отсутствие — прямая улика в пользу фильтра.

Реконструкция сессии 01.09, сходящаяся до карточки:

- 55 слов на утро были `known · step=0` со сроком **ровно `2026-09-01`**
  (стали выученными 28.08, `28.08 + 4 = 01.09`). Срок наступил →
  `wordResting` вернул `false` → слово в колоде — **это штатное поведение**.
- Четвёртая оценка «знал» дала `step=1`, `due = 01.09 + 10 = 11.09` — ровно то,
  что в состоянии.
- 55 + `to isolate` + `all over` + 3 «в работе» = **60 активных слов**, и ровно
  60 слов в `seen`. Дальше — `d:D-1`, **первый** открытый долг. То есть был один
  линейный проход по словам, по одной оценке на карточку, и остановка на первом
  долге. Ни колец, ни повторов.
- 9 слов урока B1.4 в `seen` нет, и записи SRS у них нет (в банке 88 слов, в
  `srs` — 79): сессия карточек прошла **до** того, как итог B1.4 был внесён.

Вывод: **интервалы 4/10/21 в колоде работают.** Разморозка ради A2 не нужна.

## A3. Досрочный разгон интервалов

Ответ двойной.

**Между днями разгона нет.** Симуляция «по одной оценке в назначенный день»:

```
2026-09-01 grade 1 → learning streak 1 step 0 due null
2026-09-02 grade 2 → learning streak 2 step 0 due null
2026-09-03 grade 3 → known    streak 3 step 0 due 2026-09-07   (+4)
2026-09-07 grade 4 → known    streak 4 step 1 due 2026-09-17   (+10)
2026-09-17 grade 5 → known    streak 5 step 2 due 2026-10-08   (+21)
```

Интервалы 4 → 10 → 21 отрабатываются полностью. 55 слов со `step=1` — это как
раз слова, честно доехавшие до первого настоящего отложенного повтора.

**Внутри одной сессии разгон возможен.** `deck()` вызывается **один раз** при
открытии (`journal.js:221` — `var list = deck();`), дальше всё работает по
замороженному снимку `list2` (`journal.js:246`), а `step()` кольцевой
(`journal.js:266`):

```js
        function step(n) {
          if (list2.length < 2) return;
          idx = (idx + n + list2.length) % list2.length;
          flipped = false;
          paint();                       // отметку ставит сам paint, по ключу карточки
        }
```

Оценка колоду не перестраивает. Симуляция четырёх оценок в одну дату:

```
grade 1 → learning streak 1 step 0 due null
grade 2 → learning streak 2 step 0 due null
grade 3 → known    streak 3 step 0 due 2026-09-05
grade 4 → known    streak 4 step 1 due 2026-09-11   ← 4-дневный интервал пропущен
```

То есть **если** пройти колоду по кругу больше одного раза за сессию, слово
проскочит интервал. В фактическом состоянии владельца этого не случилось (был
один линейный проход), но дыра в механике реальна: доехать до «спит» без единого
настоящего отложенного повтора можно за одну сессию из пяти кругов.

## A4. Долги в колоде

- **Количество:** все открытые, без ограничения. Сегодня — 40 из 53 карточек
  (**75 % колоды**).
- **Порядок:** `State.openDebts()` без дорожки (`state.js:875`) →
  `s.debts.filter(status==='open')` → порядок создания, от D-1 к D-41. Долги
  всегда **после** всех слов.
- **Оценок нет** — по замыслу (`journal.js:254`):
  ```js
          // оценка только у слов и только после переворота: оценивать
          // закрытую карточку нечестно, а долг карточкой не закрывается
          var canGrade = flipped && c.type === 'word';
  ```
  Долг можно только пролистать. `markSeen` при этом срабатывает
  (`journal.js:250`) — то есть долг «засчитывается» в счётчик «сегодня N»,
  ничего не меняя в состоянии.
- **Ограничения на количество за сессию нет.**

## A5. Кэп, шафл, приоритизация

**Ничего из этого нет.** Колода всегда одна и та же, от начала до конца,
«старые вперёд»:

- кэпа сессии нет — `list.length` ничем не ограничен;
- `U.shuffle` в `journal.js` не вызывается ни разу (в `state.js` он есть, но
  только в `recentWords`, `state.js:866`);
- приоритизации нет: ни «последний раз ответил не знал — вперёд», ни «слова
  последнего урока», ни группировки;
- `idx` сбрасывается в 0 при каждом `open()` (`journal.js:220`), прогресс между
  сессиями не хранится;
- признака «очередь пройдена» нет: кольцо крутится бесконечно, счётчик
  показывает `(idx+1) из N` и на 61-й карточке из 60 просто уходит на первую.

## B2. Отбор долгов в промпт — **подтверждено**

Правило: **`openDebts(trackId).slice(0, 5)`** — первые пять открытых долгов
дорожки в порядке создания. Ни ротации, ни рандома, ни учёта прогресса.

Проверка на фактах владельца (реконструкция окна на момент каждого урока):

| урок | дорожка | окно промпта (5 старейших открытых) | что реально погашено |
|---|---|---|---|
| B2.4 (28.08) | math | D-5, D-7, D-8, D-9, D-15 | **D-5, D-7, D-8, D-9, D-15** — совпадение 5/5 |
| B1.4 (01.09) | write | D-1, D-2, D-3, D-4, D-10 | **D-1, D-2, D-3, D-4, D-10** — совпадение 5/5 |

Гипотеза владельца подтверждается точно.

**Поля «когда долг последний раз брали» нет.** Структура долга целиком —
`state.js:1033`:

```js
      var debt = {
        id: U.uid(), did: nextDebtId(), track: trackId, text: text,
        createdIn: lessonId, clearedIn: [], status: 'open'
      };
```

Есть `createdIn`, `clearedIn[]`, `status`; при закрытии добавляется `closedDate`.
Момента «попал в промпт» никто не пишет.

**Поправка к формулировке «хвост из 41 долга не тронется никогда».** Очередь
строго FIFO, поэтому хвост *дойдёт* — но ждать долго, и ожидание растёт.
Симуляция очереди дорожки `write` (окно 5, +5 новых за урок, закрытие по правилу
«два разных урока»):

```

урок write #2  окно[D-11,D-12,D-13,D-14,D-34] закрыто:1  очередь:21
урок write #3  окно[D-12,D-13,D-14,D-34,D-35] закрыто:4  очередь:22
урок write #4  окно[D-35,D-36,D-37,D-38,D-39] закрыто:1  очередь:26
урок write #5  окно[D-36,D-37,D-38,D-39,D-40] закрыто:4  очередь:27
урок write #6  окно[D-40,D-41,N1,N2,N3]       закрыто:1  очередь:31  ← D-41 впервые в окне
урок write #10 окно[N9,N10,N11,N12,N13]       закрыто:1  очередь:41
```

D-41 доживёт до окна на **шестом** уроке письма, а очередь за это время вырастет
с 17 до 31.

**«Никогда» верно ровно для одной группы:** долги дорожки `biz` (D-25…D-28).
У неё `State.nextLessonInTrack('biz') === null` — доступных уроков нет, а
`memoryBlock` фильтрует строго по дорожке. В промпт минималки они тоже не
попадут: там `slice(0,3)` от всех долгов, а первые три — write-долги D-1…D-3.
Эти четыре долга видны **только в колоде карточек**, и погасить их нечем.

## B3. Два промпта подряд — что реально отличается

Урок приложение выбирает одинаково на оба дня (правило «дедлайн блока»,

# C. Долги — экономика

Факты состояния: 41 долг, **40 открытых, 1 закрыт** (D-6). Прогресс: 11 долгов на
`1/2`, 29 на `0/2`. По дорожкам: `write` 17, `math` 19 (+1 закрытый), `biz` 4,
`cs` 0. Создано по урокам: 4, 5, 5, 5, 5, 4, 5, 3, 5 — **в среднем 4,56 за урок**.

## C1. Пропускная способность и баланс

**Сколько уходит в промпт за урок:** 5 (`memoryBlock`, только своя дорожка) + 3 в
промпте минималки (всегда D-1, D-2, D-3, все дорожки).

**Правило закрытия** — `state.js:1050`:

```js
      if (debt.clearedIn.indexOf(lessonId) < 0) debt.clearedIn.push(lessonId);
      // две строки итога могли смэтчиться в один долг — считаем его один раз
      if (cleared.indexOf(debt) < 0) cleared.push(debt);
      if (uniqueLessons(debt.clearedIn).length >= 2 && debt.status === 'open') {
        debt.status = 'closed';
        debt.closedDate = date;
        closed.push(debt);
      }
```

**Теоретический максимум закрытий за урок = 5** — и только если все пять в окне
уже стоят на `1/2`. Прямо сейчас такой момент как раз наступил: на обеих живых
дорожках все пять «созревшие» (write: D-1…D-4, D-10; math: D-5, D-7, D-8, D-9,
D-15). Следующий урок каждой дорожки может закрыть 5.

**Но это разовый пик, а не режим.** Окно статично («первые 5 открытых»), поэтому
когорта из 5 требует **двух** уроков дорожки: первый ставит `1/2`, второй
закрывает. Отсюда установившаяся скорость:

```
закрытий за урок  = 5 / 2 = 2,5
создано за урок   = 4,56 (факт)      [контракт лимита не ставит — см. C3]
────────────────────────────────────
сальдо            = +2,06 долга за урок
```

**Баланс не сходится.** Симуляция в B2 подтверждает: очередь `write` растёт с 17
до 31 за 6 уроков. Реальность ещё хуже теории: за 9 уроков закрыт 1 долг, за
последние 4 урока — 0.

Что нужно, чтобы сошлось (при окне 5, дающем 2,5 закрытия за урок):

| лимит новых долгов за урок | сальдо | сходится |
|---|---|---|
| без лимита (факт 4,56) | +2,06 | нет |
| ≤5 | +2,5 | нет |
| **≤3** (предложение D4) | **+0,5** | **нет, но рост в 4× медленнее** |
| ≤2 | −0,5 | да |
| ≤3 **и окно 8 вместо 5** | −1,0 | да |

Вывод по D4: **одного лимита ≤3 недостаточно** — он замедляет рост, но не
разворачивает его. Разворачивает либо ≤2, либо ≤3 в паре с расширением окна
промпта до 8, либо приоритет `1/2` в окне (см. D3, он даёт 5 закрытий за урок).

## C3. Где в контракте ограничение числа новых долгов

**Его нет нигде.** Четыре места, где оно могло бы стоять, и что там на самом деле:

1. **Шаблон итога** (`prompts.js:156`):
   ```js
      'Долги: <новые слабые места, каждый с новой строки, или «нет»>',
   ```
   Сравните со строкой выше — `'Слова (8–12): слово — перевод; ...'`
   (`prompts.js:155`). У слов числовой диапазон есть, **у долгов — нет**.

2. **Правило 14 контракта** (`prompts.js:139`) ограничивает **длину**, а не
   количество:
   > «…Новые долги формулируй в ≤12 слов.»

3. **Правило 12** (`prompts.js:137`) — качественный фильтр, не числовой:
   > «Описки и мелочи — одной строкой без остановки урока и БЕЗ занесения в
   > долги; в долги только смысловое или повторяющееся.»

4. **Приёмник** `applySummary` (`state.js:1026`) создаёт **каждый** разобранный
   долг; единственная защита — дедуп по идентичному нормализованному тексту
   **из того же самого урока**:
   ```js
    var created = [];
    (parsed.debts || []).forEach(function (text) {
      var key = normText(text);
      var dup = s.debts.some(function (x) {
        return x.createdIn === lessonId && normText(x.text) === key;
      });
      if (dup) return;
   ```
   Тот же долг из **другого** урока дедупом не считается — так в банк и легли
   D-13/D-37, D-34/D-38, D-36/D-40.

**Почему «не держит»: держать нечему.** ИИ видит только «каждый с новой строки»,
ориентируется на соседнюю строку «Слова (8–12)» и стабильно выдаёт 4–5. Разброс
3–5 по девяти урокам — это разброс модели, а не работа ограничителя.

# Находки вне списка (правило релея — описано, не чинится)

### Р1. ИИ выдумывает `[D-N]` для новых долгов, и один такой id погасил чужой долг

Сырой итог B1.3 (29.08):
```
Погашено:
[D-11] название шага не совпадает с действием
Долги:
[D-12] Пропускает артикль the перед конкретными величинами
[D-13] В письме пишет голые формулы вместо полных предложений
[D-14] Because начинает отдельное предложение вместо запятой
```
В промпте B1.3 показывались долги `[D-1] … [D-4], [D-10]`. ИИ продолжил
нумерацию сам. Последствия:

1. **Ложное погашение.** `matchDebt` (`state.js:937`) первым ярусом читает
   `DEBT_ID_RE` из строки «Погашено» и нашёл **D-11** — долг, которого в промпте
   не было и над которым на уроке не работали. Сейчас у него
   `clearedIn: ["B1.3"]`, то есть `1/2` незаслуженно.
2. **Отравленный текст.** D-34…D-41 записаны в банк **вместе с чужим id внутри
   текста** (`«[D-12] Пропускает артикль…»`). Правило 14 (`prompts.js:139`) прямо
   велит: «копируй формулировку долга ДОСЛОВНО, символ в символ». Если ИИ
   выполнит правило 14 для D-38, строка «Погашено» будет содержать `[D-12]` — и
   `matchDebt` погасит **D-12**, а не D-38. Перекрёстная ошибка уже заряжена;
   контракт её не предотвращает, а провоцирует.
3. Ни `applySummary`, ни парсер ведущий `[D-N]` из текста нового долга не
   срезают.

Масштаб: **8 из 40 открытых долгов** несут чужой id (D-34…D-41), плюс одно
ложное погашение.

### Р2. `toList` режет долг по точке с запятой — один долг стал двумя

`prompts.js:353`:
```js
  function toList(raw) {
    if (!raw) return [];
    return String(raw)
      .split(/\r?\n|;/)
```
Комментарий над функцией утверждает: «Точка с запятой разделителем остаётся: так
эти поля и пишет ИИ … и внутри формулы её не бывает». **В долгах бывает.**

Сырой итог B2.1 содержал 4 строки долгов, в банк легло 5. Разрезана строка:
```
Шаблон «m = …, which is the …; b = …, which is the …» не автоматизирован — требуется устно, без подсказки
```
→ **D-6** = `Шаблон «m = …, which is the …` (бессмысленный огрызок)
→ **D-7** = `b = …, which is the …» не автоматизирован — требуется устно, без подсказки`

Иронично: **D-6 — единственный закрытый долг за всё время**, и закрылся он именно
потому, что огрызок короткий и целиком попал внутрь перефраза ИИ
(`want.indexOf(have) >= 0` → score 1.0). Его вторая половина D-7 в тех же двух
уроках не смэтчилась и висит открытой.

### Р3. Порог `SIM_MIN = 0.85` не ловит перефраз — до 2.6.0 долги почти не гасились

`state.js:888` — `var SIM_MIN = 0.85;`. Прогон реальных строк «Погашено» из
B2.2 / B2.3 / B1.2 против текстов долгов, той же функцией `State.similarity`:

```
D-5  sim=0.634  вхождение: нет  → НЕ смэтчился
D-9  sim=0.598  вхождение: нет  → НЕ смэтчился
D-7  sim=0.729  вхождение: нет  → НЕ смэтчился
D-6  sim=1.000  вхождение: ДА   → смэтчился
D-1  sim=0.343  вхождение: нет  → НЕ смэтчился
```

Отсюда и «закрыто 0» до 2.6.0. Как только в промпт добавили `[D-N]`, погашение
стало срабатывать **5/5** (B2.4 и B1.4). То есть текстовый ярус `matchDebt` на
практике мёртв: работает только id.

Дополнительно: B1.2 записал «Погашено» одной строкой с разделителем `·`.
`toList` режет только по `\n` и `;` — вся строка ушла в `matchDebt` целиком,
получила `sim = 0.343` и не погасила **ничего**.

### Р4. Обещание «колода не растёт, а сокращается» не выполняется

`app.js:477` — «Колода от этого не растёт, а сокращается». Фактически: 40 долгов
из колоды не уходят никогда, а 55 слов синхронно возвращаются 11.09, поднимая
колоду с 53 до 128 карточек. Формулировка верна только для отдельно взятого
слова, не для колоды.

### Р5. Когортная синхронизация сроков

Все 55 слов получили `due = 2026-09-11` в один день. Интервалы фиксированные
(`[4, 10, 21]`, `state.js:729`), джиттера нет, поэтому когорта, однажды выученная
вместе, будет возвращаться вместе и дальше: 11.09 → 02.10 → сон. Пики
предсказуемы и будут повторяться.
